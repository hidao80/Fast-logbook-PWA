# Development Workflow

React 19 + TypeScript 6 + Vite 8, package manager pnpm 10.33.2 (pinned via `packageManager` field in `package.json`). This supersedes the older vanilla-JS/`js/lib/` architecture.

## CI wiring (`.github/workflows/`, verified directly)

Two workflows exist, both triggered **only** on `push` to `branches: [main, develop]`. Neither has a `pull_request:` trigger, contradicting `AGENTS.md`'s claim that CI runs "on push/PR to main/develop."

- **`lint.yml`**: checkout (`actions/checkout@v6`) → `flatt-security/setup-takumi-guard-npm@v1` → `mongolyy/reviewdog-action-biome@v1` with `reporter: github-pr-review`. Using a PR-review reporter on a `push`-only trigger is inconsistent — `reviewdog`'s `github-pr-review` reporter is designed to post inline review comments on a pull request event; without a `pull_request` trigger it has no PR context to attach comments to on a plain push. This is a plausible CI-configuration bug, not confirmed by running it. ⭐⭐⭐ (worth verifying/fixing, but low urgency since `push` to `main`/`develop` still executes the job).
- **`audit.yml`**: checkout → takumi-guard setup → `pnpm/action-setup@v4` → `actions/setup-node@v4` (Node 24, pnpm cache) → `pnpm install --frozen-lockfile` → `pnpm audit --audit-level=high`.

Neither workflow runs `build`, `lint` failure gating for merges (no `pull_request` trigger means lint doesn't block PR merges automatically), or the Playwright E2E suite. There is no CI job that runs `pnpm run build` or `pnpm test`. This means broken builds or E2E regressions are not caught by GitHub Actions before merge to `main`/`develop` — only lint/format issues (post-push, non-blocking for PRs) and dependency audit findings are checked.

Note on build health: commit `ceff98a` in the git history removes the root `index.html`, but the current working tree has it back as an untracked file (confirmed via `git status` at task start), so the local build currently succeeds. This is a git-history vs. working-tree gap worth being aware of for CI robustness discussions — it is not evidence of an actually broken build right now, but it does mean a clean checkout from `ceff98a` without the untracked file would fail to build, and no CI job would currently catch that since there is no `build` step in either workflow. ⭐⭐⭐⭐ recommend adding a `build` (and ideally `test:e2e`) job gated on `pull_request` to `main`/`develop`.

## Branching model and commit conventions

`git branch -a` shows: current branch `develop`, plus local `add-dirty-and-saved-lamp`, `main`, and remote-only `origin/add-help-screen`, `origin/add-remove-dialog`. This indicates a `main` + `develop` two-tier trunk model with short-lived feature branches (`add-*`) merged in via PR (evidenced by `#20`, `#19` in commit messages) or directly.

Commit message convention is a **mix**, confirmed via `git log --oneline -20`:
- Conventional Commits: `fix:`, `chore:`, `feat:` (majority of recent commits, e.g. `fix: correct version number...`, `chore: add pnpm workspace overrides...`, `feat: add initial HTML structure...`).
- Gitmoji-prefixed, non-conventional messages still appear further back in history: `:art: Update .actrc...`, `:art: Add .actrc configuration...` — these predate the more recent Conventional-Commits-only run but remain in the log within the last 20 commits, so the convention is not fully consistent even in recent history.
- Some merges reference PR numbers in parentheses, e.g. `(#20)`, `(#19)`, indicating GitHub PR merges are also part of the flow alongside direct commits.

No `CONTRIBUTING.md` or explicit commit-convention policy document was found in this pass; the convention is inferred from `git log` only, not documented anywhere in `AGENTS.md`/`CLAUDE.md`. Unconfirmed whether a commit-lint hook or CI check enforces Conventional Commits — none was found in `.github/workflows/` or `package.json` devDependencies (no `commitlint`, `husky`, or `commitizen` packages present).

## Lint/format (Biome) usage

- `biome check src/` (plain check) and `biome check --write src/` (auto-fix) are the two entry points, scoped to `src/` only.
- Config lives in `biome.json` (not re-verified line-by-line in this pass; prior-pass findings cited in project rules describe 2-space indent, LF, single quotes, semicolons — consistent with the `.claude/rules/code-style.md` project rule file).
- CI enforcement is push-only via `lint.yml` (see CI section above) using a third-party reviewdog action rather than running `pnpm run lint` directly as `AGENTS.md` claims — this is a discrepancy between documented and actual CI lint invocation. The workflow does not literally run `pnpm run lint`; it runs Biome through `reviewdog-action-biome`, a separate composite action. Unconfirmed whether that action internally reads the same `biome.json` config or applies equivalent rules.

## Versioning scheme

Version string `26.07.19` follows a CalVer-like `YY.MM.DD` pattern (year.month.day), not SemVer. Confirmed current value in `package.json`: `"version": "26.07.19"`.

Grep across the repo (excluding `node_modules`) confirms the version string `26.07.19` appears in at least these files:
- `package.json` (source of truth, presumably)
- `src/i18n/locales/en.json`
- `src/i18n/locales/ja.json`
- `dist/manifest.json` (build output, not source — regenerated by `vite build`, so not an independent manual-update site)
- `.claude/analyzed/ADR.md`, `.claude/analyzed/configurations.md`, `.claude/analyzed/development-workflow.md` (the file being replaced by this pass), `.claude/analyzed/known_bugs.md` — these are prior analysis-doc artifacts referencing the version, not app source.

Excluding build output and analysis docs, the version is manually duplicated across at least **3 source files** (`package.json`, `src/i18n/locales/en.json`, `src/i18n/locales/ja.json`), confirming the scattered-version-bumps issue from the prior pass, though the count is 3 source files rather than "6+" once build artifacts and doc snapshots are excluded — those categories don't require a human to remember to update them (build output regenerates; doc snapshots are this analysis pipeline's own output). The two most recent commits (`da702ec`, `68aa9d2`) show this is an active pain point: a version bump introduced a typo (`26.07/19` instead of `26.07.19`) that had to be corrected in a follow-up commit, evidence that manual, unvalidated duplication across files is error-prone in practice. No `.releaserc`, `standard-version`, or other automated version-bump tooling was found in `package.json` devDependencies. Recommendation: single-source the version (e.g. generate the i18n locale strings from `package.json` at build time via a Vite define/plugin, or a pre-commit/CI check that asserts all copies match) rather than hand-editing each file. ⭐⭐⭐⭐⭐ (directly caused a real, recently-fixed bug).

## Summary of workflow gaps found in this pass

1. `AGENTS.md` Architecture section is stale (vanilla-JS description) and self-contradicts its own later section — confirmed present as of `ceff98a`.
2. CI workflows trigger on `push` only, not `pull_request`, despite `AGENTS.md` documenting push/PR triggers — confirmed via direct read of both YAML files.
3. `lint.yml` uses a PR-review-style reviewdog reporter on a non-PR trigger — plausible misconfiguration, unconfirmed by execution.
4. No CI job runs `build`, `test`/`test:e2e`, or `test:e2e:headed` — confirmed absent from both workflow files.
5. Commit convention is a mix of Conventional Commits and gitmoji, undocumented anywhere — confirmed via `git log`.
6. Version string is manually duplicated across 3 source files with no single-source mechanism, and this already caused one real typo bug — confirmed via grep and commit history.
